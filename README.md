# Auto Weight Backend

รับข้อมูลน้ำหนักจากเครื่องชั่ง (ต่อผ่าน TCP แบบเดียวกับที่ Hercules SETUP utility ใช้ทดสอบ)
แล้วบันทึกลงตาราง `Auto` เดิมใน SQL Server (คอลัมน์ `id`, `weight`, `time_stamp` — **ไม่ต้องแก้โครงสร้างตารางเดิม**)

## ติดตั้ง

```bash
pip install -r requirements.txt
```

## ตั้งค่า

คัดลอก `.env.example` เป็น `.env` แล้วแก้ค่าตามจริง:

```
DEVICE_IP=192.168.1.111
DEVICE_PORT=1052

DB_SERVER=172.48.0.115       # แก้เป็น host จริงของ SQL Server ที่รัน AUTO_WEIGHT DB
DB_NAME=AUTO_WEIGHT
DB_USER=PFCMv2
DB_PASSWORD=987654321.Com
```

## รัน

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

พอรันแล้ว backend จะ:
1. ต่อ TCP ไปที่ `DEVICE_IP:DEVICE_PORT` อัตโนมัติ (เหมือนตอนกด Connect ใน Hercules)
2. อ่านข้อมูลดิบที่ส่งมา เช่น `GW+ 0052.5 g,cx11,` หรือ `07GW+ 0045.5 g,cx11,`
3. ดึงเฉพาะตัวเลขน้ำหนัก (`0052.5` → `52.5`) ด้วย regex
4. Insert ลงตาราง `Auto` ทันทีที่เจอค่าน้ำหนัก
5. ถ้าหลุดการเชื่อมต่อ จะพยายามต่อใหม่อัตโนมัติทุก 5 วินาที

## ตรวจสอบสถานะ

- `GET /status` — ดูว่าต่อเครื่องชั่งอยู่ไหม, ค่าน้ำหนักล่าสุด, จำนวนที่รับมาแล้ว
- `GET /recent?limit=20` — ดึงแถวล่าสุดจากตาราง Auto (เทียบกับ query เดิมของคุณ)
- `POST /stop` / `POST /start` — หยุด/เริ่มการอ่านข้อมูลจากเครื่องชั่ง

## หมายเหตุสำคัญ

- โค้ดนี้ **ไม่แก้โครงสร้างตาราง Auto** ใช้แค่ 2 คอลัมน์ที่ insert ได้คือ `weight` และ `time_stamp`
  (`id` ปล่อยให้เป็น identity auto-increment ตามเดิม)
- Prefix ตัวเลขนำหน้า `GW+` (เช่น `07`, `01`) **ยังไม่ได้เก็บ** เพราะตารางเดิมไม่มีคอลัมน์รองรับ
  ถ้าต้องการเก็บ ต้องเพิ่มคอลัมน์ในตารางก่อน (แจ้งได้ถ้าต้องการ)
- ถ้าเครื่องชั่งส่งข้อมูลมาถี่มาก และอยากกันไม่ให้ insert ถี่เกินไป ปรับค่า `MIN_INSERT_INTERVAL_SEC`
  ในไฟล์ `main.py` ได้ (ตอนนี้ตั้งเป็น 0 คือ insert ทุกค่าที่อ่านได้)
- ควรรันเป็น service (systemd / Windows Task Scheduler / Docker) เพื่อให้ backend ทำงานตลอดเวลา

## อัปเดต v2 — รองรับหลายเครื่องชั่ง + หน้า Monitor / Dashboard / ประวัติ

โครงสร้างใหม่: sidebar (hamburger เปิด/ปิดได้) มี 3 หน้า
- **Monitor** (`monitor.html`) — เครื่องชั่งทั้งหมด สลับมุมมอง Card/Table ได้, สถานะ on/off, เลือก Group→Product Code + ชื่อผู้ตรวจสอบ แล้วกด "เริ่ม/หยุด" (1 รอบ = 1 เอกสาร), แก้ไขเวลาเริ่ม/หยุดของเอกสารที่กำลังทำได้, ลิงก์ไปกราฟของแต่ละเครื่อง
- **Dashboard** (`dashboard.html`) — กราฟ SPC เดิม ดูได้ทีละเครื่อง (`dashboard.html?scale=<id>`), มีแถบเริ่ม/หยุดเอกสารในตัว (พร้อมชื่อผู้ตรวจสอบ + แก้ไขเวลา), คำนวณ Cp/Cpk สดแล้วแจ้งเตือนด้วยเสียงต่อเนื่องถ้าต่ำกว่าเกณฑ์ที่ตั้งไว้ในหน้าตั้งค่า
- **ประวัติ** (`history.html`) — ตารางเอกสารทั้งหมด sort/filter ได้ทุกคอลัมน์ รวม Line/S-N และวันที่ตามกะโรงงาน (DS/NS) แต่ละแถวมีปุ่ม **Export PDF** (ใช้แม่แบบเดียวกับ Dashboard ดึงค่าน้ำหนักตามช่วงเวลาเริ่ม-หยุดจริง) และปุ่ม **แก้ไขเวลา** (ต้องใส่รหัสผ่าน ตั้งค่าได้ที่หน้า "ตั้งค่า") ลิงก์ไปหน้า **รายละเอียดเอกสาร** (`session.html?id=<id>`) ที่แสดงสรุปผล + กราฟค่าน้ำหนักดิบทั้งหมดของเอกสารนั้น
- **ตั้งค่า** (`config.html`) — ปรับเกณฑ์แจ้งเตือน Cp/Cpk/Ppk ต่ำสุด, เกณฑ์ของหลุด Spec ย้อนหลังตามช่วงเวลา (เช่น "ทุก 1 ชม. ห้ามหลุดเกิน N ค่า" หรือ "ห้ามหลุดเกิน N%"), เกณฑ์ค่าเฉลี่ยเบี่ยงเบนจาก Target, เปิด/ปิดเสียงเตือน, และรหัสผ่านแก้ไขเวลาในหน้าประวัติ (ซ่อนเป็นจุด ๆ ไม่โชว์บนจอ)

### ขั้นตอนติดตั้ง (จากของเดิม)

1. **รัน migration บน SQL Server** (เพิ่มตาราง `Scales`, `Sessions` และคอลัมน์ใหม่ใน `Auto` — ไม่กระทบข้อมูลเดิม):
   ```bash
   sqlcmd -S <DB_SERVER> -d AUTO_WEIGHT -U <user> -P <password> -i backend/sql/migrate_v2_multiscale.sql
   sqlcmd -S <DB_SERVER> -d AUTO_WEIGHT -U <user> -P <password> -i backend/sql/migrate_v3_session_product_info.sql
   sqlcmd -S <DB_SERVER> -d AUTO_WEIGHT -U <user> -P <password> -i backend/sql/migrate_v4_inspector_and_settings.sql
   ```
   `migrate_v3` เพิ่มคอลัมน์ package/package_name/customer/destination/label_ink ใน `Sessions` เพื่อให้ใบพิมพ์ WEIGHT CHECK RECORD และหน้ารายละเอียดเอกสารแสดง SIZE/CUSTOMER จริงได้ (ไม่ต้อง query กลับ DB ตัวที่สองทุกครั้ง)
   `migrate_v4` เพิ่มคอลัมน์ `inspector_name` ใน `Sessions` และสร้างตาราง `Settings` (key-value) เก็บเกณฑ์แจ้งเตือน Cp/Cpk/Ppk + รหัสผ่านแก้ไขเวลาในหน้าประวัติ (ปรับได้ทีหลังผ่านหน้า "ตั้งค่า" ในเว็บ ไม่ต้องแก้ SQL อีก)
   `migrate_v5` เพิ่มค่า default สำหรับเกณฑ์แจ้งเตือนของหลุด Spec ย้อนหลัง/ค่าเฉลี่ยเบี่ยงเบน (ไม่รันก็ได้ — พอกด "บันทึก" ครั้งแรกที่หน้าตั้งค่า ระบบจะสร้าง key ให้เองอัตโนมัติ)
   `migrate_v6` เพิ่มคอลัมน์ `remark` ใน `Sessions` (หมายเหตุอิสระตอนเริ่มเอกสาร แสดงในช่อง REMARK ของใบพิมพ์) และค่า default `report.formCode` (รหัสฟอร์ม/document control number ที่พิมพ์บนหัวใบ WEIGHT CHECK RECORD — แก้ได้ที่หน้าตั้งค่า)

   ในไฟล์ v2 มี `INSERT` seed เครื่องชั่งตัวแรกจากค่าเดิมใน `.env` (`172.48.2.175:1052`) — แก้ ip/port/line/serial_no ในไฟล์ก่อนรัน หรือจะลบ block นั้นแล้วไปเพิ่มเองผ่านหน้า Monitor ทีหลังก็ได้ เครื่องอื่นที่เหลือ (รวม 13 เครื่อง) เพิ่มผ่านปุ่ม **"+ เพิ่มเครื่องชั่ง"** ในหน้า Monitor ได้เลย ไม่ต้องแก้ `.env` อีก

2. **ตรวจ `.env`** — เพิ่มบล็อก `DB_USER_WC` / `DB_PASSWORD_WC` / `DB_SERVER_WC` / `DB_DATABASE_WC` / `PORT_WC` แล้ว (เชื่อมต่อ DB ตัวที่สอง อ่านอย่างเดียว สำหรับดึง GroupCode/ProductCode + spec จาก `TunaCodes`)

3. **ติดตั้ง dependency ใหม่ไม่ต้องมี** — ใช้ `mssql` เดิมที่มีอยู่แล้ว รันตามปกติ:
   ```bash
   cd backend && npm install && cd ../frontend && npm install
   pm2 start ecosystem.config.js   # หรือ npm start ในแต่ละโฟลเดอร์ตอน dev
   ```

4. เข้าเว็บที่ `http://<FRONTEND_HOST>:3000/` จะ redirect ไปหน้า **Monitor** อัตโนมัติ

### จุดที่ควรรู้

- **ค่าน้ำหนักทุกเครื่องเก็บในตาราง `Auto` เดียวกัน** (ตามที่ตกลง — จัดการง่ายกว่าแยกตารางต่อเครื่อง) แยกด้วยคอลัมน์ `scale_id` + มี index `(scale_id, time_stamp)` และ `session_id` รองรับ 13 เครื่องได้สบายแม้ข้อมูลสะสมหลักล้านแถว ถ้าในอนาคตข้อมูลโตมากจนช้า ค่อยพิจารณา partition ตาราง `Auto` ตาม `time_stamp` เพิ่มได้ทีหลังโดยไม่ต้องแก้โค้ด backend
- **1 เอกสาร (session)** เก็บทั้งสรุปผล (avg/min/max/count/จำนวนเกินเกณฑ์) และ join ย้อนดูค่าน้ำหนักดิบทุกค่าได้ผ่าน `GET /api/sessions/:id/weights`
- **กะโรงงาน**: 06:00–17:30 = DS ของวันนั้น, 17:30–06:00 (ข้ามเที่ยงคืน) = NS ของ "วันที่กะเริ่ม" ไม่ใช่วันที่จบ คำนวณอยู่ใน `backend/src/shift.js`
- **spec (Target/UCL/UWL/LWL/LCL)** ถูก snapshot ลงในเอกสารตอนกด "เริ่ม" กันปัญหา spec เปลี่ยนทีหลังแล้วประวัติเก่าตีความผิด
- ปิด backend กลางคันตอนมีเอกสารค้าง `running` อยู่ — เปิดใหม่แล้ว backend จะ "กู้คืน" เอกสารนั้นกลับมาเป็น active ให้อัตโนมัติ (ดู `scale-manager.js#init`)
- **ลบเครื่องชั่ง**: ถ้าเครื่องนั้นยังไม่เคยมีเอกสาร/ค่าน้ำหนักเลย ระบบจะลบออกจากทะเบียนถาวร แต่ถ้ามีประวัติผูกอยู่แล้ว (ติด FK constraint กับตาราง `Sessions`/`Auto`) ระบบจะ **ปิดใช้งานแทน** (หยุดการเชื่อมต่อ + ซ่อนจากหน้า Monitor) เพื่อไม่ให้ประวัติเก่าหายหรือ error กลางทาง — แถวยังอยู่ใน `dbo.Scales` (enabled=0) เผื่อจะ query ย้อนหลังหรือเปิดใช้ใหม่ในอนาคต (ตอนนี้ยังไม่มีปุ่ม "เปิดใช้งานเครื่องที่ปิดไว้" ใน UI — ทำได้ผ่าน `UPDATE dbo.Scales SET enabled=1 WHERE id=...` ชั่วคราวก่อน)
- **ไม่เก็บ "ชื่อเครื่องชั่ง" แยกแล้ว**: ฟอร์มเพิ่ม/แก้ไขเครื่องชั่งเหลือแค่ IP/Port/Line/S-N — ทุกหน้าใช้ **Line** เป็นหัวข้อ/ป้ายแสดงผลแทน (คอลัมน์ `name` ใน DB ยังอยู่เพื่อความเข้ากันได้ backend จะตั้งให้อัตโนมัติ = Line หรือ IP ถ้ายังไม่มี Line)
- **Cp/Cpk/Ppk แจ้งเตือนเสียง**: หน้า Dashboard คำนวณ Cp/Cpk จากข้อมูลที่กำลังแสดงอยู่ (ตาม Range ที่เลือก) ทุกครั้งที่ข้อมูลอัปเดต เทียบกับเกณฑ์ในหน้า "ตั้งค่า" ถ้าต่ำกว่าเกณฑ์จะขึ้นป้ายแดงกะพริบ + เสียงเตือนวนซ้ำทุก 0.7 วินาทีจนกว่าจะกด "หยุดเสียงเตือน" หรือค่ากลับมาปกติ (หมายเหตุ: ระบบยังไม่ได้แยกสูตร Ppk จาก Cpk จริง เพราะยังไม่ได้เก็บข้อมูลแบบ subgroup — ตั้งเกณฑ์ Ppk แยกไว้รอได้ แต่ค่าที่คำนวณตอนนี้เท่ากับ Cpk)
- **รหัสผ่านแก้ไขเวลาในหน้าประวัติ** default คือ `172480116` เปลี่ยนได้ที่หน้า "ตั้งค่า" (หน้า Monitor/Dashboard แก้ไขเวลาได้โดยไม่ต้องใส่รหัสผ่าน เพราะเป็นการแก้ไขเอกสารที่กำลังทำงานอยู่ ไม่ใช่ประวัติเก่า)
- **กันพัง `/api/sessions/:id`, `/api/scales/:id`**: ทุก route ที่รับ `:id` ตรวจแล้วว่าต้องเป็นตัวเลขล้วนก่อนส่งต่อไปที่ SQL Server (`sql.Int`/`sql.BigInt`) ถ้าไม่ใช่ตัวเลข (เช่นมี request หลุดมาที่ `/api/sessions/start` ด้วย method ผิด แทนที่จะเป็น POST) จะตอบ `400` กลับไปเฉย ๆ แทนที่จะโยน `RequestError` ที่ทำให้ backend log error รัว ๆ ทุกไม่กี่วินาทีเหมือนที่เคยเจอในเวอร์ชันก่อนหน้า
- **Group Code / Product Code ค้นหาได้**: ช่องเลือกในหน้า Monitor และ Dashboard เปลี่ยนจาก dropdown ธรรมดาเป็นช่องพิมพ์ค้นหา (native `<datalist>`) — พิมพ์บางส่วนของรหัสแล้วเลือกจากรายการที่กรองได้เลย ถ้าพิมพ์ค่าที่ไม่ตรงกับรายการจริงระบบจะเตือนก่อนเริ่มเอกสาร
- **หมายเหตุ (Remark) ต่อเอกสาร**: กรอกได้ตอนเริ่มเอกสาร (หน้า Monitor/Dashboard) และแก้ไขได้ทีหลัง (ทั้ง 3 หน้า) จะไปแสดงในช่อง REMARK ของใบพิมพ์แทนข้อความอัตโนมัติเดิม ถ้าไม่กรอกอะไรไว้ ระบบจะ fallback ไปใช้ข้อความอัตโนมัติเหมือนเดิม
- **รหัสฟอร์ม/Document No. บนใบพิมพ์**: ปรับได้ที่หน้าตั้งค่า (ค่า default `F3QCPFB8-1-01/9/2025`) แสดงแทนเลข session เดิมที่หัวใบ WEIGHT CHECK RECORD
- **Size บนใบพิมพ์**: รวมทั้ง `Package` (ขนาด เช่น "3.7 Oz.") และ `PackageName` (คำอธิบาย เช่น "Round cup") จาก DB(WC) เข้าด้วยกัน
